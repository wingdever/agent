# 无人值守任务周期

## 范围

本文件定义**无人值守任务周期**：一个目标在没有人类干预的整段时间里被持续推进，直到完成、到达截止条件或人类主动中止。

它是一类任务的运行方式，不是某一个实现。本文写这类周期要回答的问题和一个方案的准入判据；具体方案各自成文，当前候选只有 pusher–worker（`docs/agents/pusher-worker.md`）。

与"长任务"的区别：长任务可以跨轮、可以很长，但允许在每个阶段插进人类交互（确认、补充、驳回），人类在场是正常路径。无人值守任务周期把"人类不在场"当默认状态来设计：人类不在场不是异常，人在场的插入是偶发事件。

## 1 必须回答的问题

任何方案要实现无人值守，都要对下面每一条给出明确答案；没有答案的方案在这一类任务里不成立。

### 1.1 谁在没人输入时开下一轮

无人值守的核心是"没有人类调用 agent，也要继续"。这要求有东西在会话空闲时判定"该继续"并开轮。开轮的接入方式是轮次来源（`docs/agents/lifecycle.md` §2）；来源可以是周期自己的驱动器，也可以复用其它模块已有的续轮能力。

### 1.2 目标与完成怎么表示

周期要有一个能独立判断"做完了没有"的目标表示：可以是持久目标对象（如 goal），可以是任务清单的状态，也可以是周期自己维护的进度事实。要求是：

- 完成判定可被规划方以外的观察者复核；
- 终止后留下可回顾的产出事实，而不是一句自述。

### 1.3 计划从哪来、谁能改

周期开工前的计划（任务块、依赖、验收标准）要有一个可读写的载体。计划载体的所有权必须唯一：谁建块、谁改块、谁判定块完成，同一时刻只有一个角色能写。计划变更走提议—采纳，不允许执行方自己改验收标准。

### 1.4 失败与阻塞怎么自愈

无人值守时没有人来点"继续"，因此失败不能直接变成挂起。方案要给出分级：

- 可重试的失败：由谁重试、重试几次；
- 重试耗尽的失败：换执行者、降级范围，还是记阻塞；
- 只有哪些情况允许停下等人。

"停下等人"必须是方案里能数出来的少数情况，不能是默认兜底。

### 1.5 什么算截止

截止分两类，方案要都覆盖：

- **可判定截止**：轮次上限、时间窗、总花费上限；
- **语义截止**：目标达成、计划耗尽、连续无进展。

语义截止需要可观察的判据（任务状态变化、产出物出现），不能只依赖执行方自述。

### 1.6 人类怎么介入、怎么回顾

无人值守不等于禁止人类介入，而是介入是例外：

- **介入**：随时可发消息、可暂停、可打断当前执行；介入不能要求先走一套审批。
- **回顾**：周期结束后人类一次性检查产出与过程记录。过程记录要能回答"做了什么、花了多少、卡在哪"。

### 1.7 上下文与成本怎么控制

周期可能比一次人工会话长出很多。方案要说明：

- 执行者的上下文怎么累积、什么时候压缩；
- 规划方的上下文怎么避免被执行细节撑爆；
- 成本按什么计量、在哪看。

## 2 方案的准入判据

一个新方案要进入本类任务，至少要同时满足：

1. **开轮有明确来源**：在会话空闲时由谁开轮、依据什么条件，写死在方案里，不靠外部调用方；
2. **完成与截止可复核**：§1.2、§1.5 的判据能被周期之外的观察者按事实复核；
3. **失败不挂起**：§1.4 的自愈路径完整，停下等人的条件可数；
4. **人类介入是例外路径且不被阻断**：§1.6 的介入能力在无人值守同样可用；
5. **不依赖人类在场的审批**：需要审批的动作要么提前批准，要么被方案明确排除；
6. **跨重启有说法**：进程重启、应用关闭再打开之后，周期继续、暂停还是结束，方案要写明并可从持久事实恢复该判断。

不满足第 5 条（依赖审批才能推进）的方案只能算"长任务"，不属于无人值守。

## 3 与既有能力的关系

- **goal**：单会话的持久目标与自动续轮，按 DSH 的语义实现；它本身不是无人值守任务周期，也不为无人值守做任何预留。
- **todo / team task / schedule / jobs / subagents**：都是可选的零件。方案可以选择引用，也可以自带一套；选哪一套属于方案自身的决定。

无人值守任务周期**可以完全不用 goal**；需要的时候也可以只用 goal 的某一部分（例如只借它的目标状态），但这是方案自己的接法，不改变 goal 的语义与实现。
