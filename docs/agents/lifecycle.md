# 轮次生命周期

## 范围

本文件定义 agent 实例与运行时对外暴露的两个通用扩展点，以及它们在轮次上的契约：

- **轮次事件**：实例在每个生命周期节点同步发出的事件，功能模块订阅后自己决定怎么响应。
- **轮次来源**：能在会话空闲时主动开起一轮的外部生产者，按优先级询问。

运行时、工具执行与 loop 节点都不认识具体功能。goal、pusher–worker、schedule、jobs 这类需要"无人值守时自己开下一轮"的能力，一律通过这两个接口接入，不在 `chat()` 里、也不在 loop 节点里写功能分支。

## 1 轮次事件

### 1.1 订阅

```js
const off = agent.on("turn:end", (payload) => { ... });
off(); // 取消订阅
```

- 订阅只属于该实例；实例被释放后订阅随之失效。
- 回调**同步**触发，返回值忽略。需要异步处理的模块自己排队，不阻塞轮次。
- 订阅者抛出的异常被吞掉并记一条警告：一个观察者出错不能打断轮次。

### 1.2 事件表

| 事件 | 时机 | payload |
|---|---|---|
| `session:start` | 实例第一次由外部输入开轮之前，每实例一次；由轮次来源开的轮不触发（来源只继续已经活着的会话） | `{ agent, turn }` |
| `turn:start` | `beginTurn` 打开轮次后 | `{ agent, turn }`（`turn.claim`、`turn.deferred` 已就位） |
| `turn:end` | 轮次真正结束、实例回到空闲之后 | `{ agent, status, reason, steps, tools, durationMs, claim }`（`reason=claim-failed` 表示来源要求在轮首的持久化失败） |
| `turn:cancelled` | 有人调用实例的 `interrupt()` | `{ agent, cause? }`（`cause` 由调用方传入） |
| `inbox:queued` | 一条输入进入任一队列 | `{ agent, queue, item }` |
| `inbox:claimed` | 一条输入被领取（`next-turn` 轮首、`next-step` 步边界） | `{ agent, queue, item }` |
| `inbox:removed` | 一条尚未被领取的输入被移除（含预留作废） | `{ agent, queue, item }` |

`session:start` 只表示"这个实例在本进程里第一次要开始一个会话"，实例之后的空转与重开不再发；实例重建（进程重启后重新打开会话、恢复、fork）会重新发一次。来源开的轮带上 `claim`，它属于"已经在继续的会话"，因此不触发该事件。

### 1.3 轮次上的通用字段

轮次对象（`agent.turn`）只承载与本轮发起方式有关的通用字段，不含任何功能名：

| 字段 | 含义 |
|---|---|
| `claim` | 本轮由哪个来源发起、以及该来源要求在轮首持久化的内容；没有来源发起时为 `null` |
| `deferred` | 工具在执行中延迟提交、要在下一 step 之前追加给模型的上下文（如收尾指令） |

`claim` 的形状由来源自己解释，运行时只保证它在 `turn:start` 之后、轮首持久化之前可读，并在轮首持久化点被调用一次。

## 2 轮次来源

### 2.1 登记

```js
const unregister = runtime.registerTurnSource({
  name: "goal",            // 稳定标识，用于诊断与去重
  priority: 100,           // 可选；缺省取默认层（见 2.3）
  admit: async (agent) => {
    // 返回 { message: { content, source }, claim }, 或 null 表示"这一轮我不要"
  },
});
```

- 登记是进程级的；运行时不持久化来源，进程退出即清空。
- `name` 只用于诊断与去重：同名登记以最后一次为准。
- 一个来源可以只对部分会话感兴趣：`admit(agent)` 自己判断，不关心时返回 `null`。

### 2.2 询问

会话**空闲**、调用方请求开一轮时，运行时按优先级询问已登记的来源：

1. `admit(agent)` 返回 `null` → 问下一个；
2. 返回 `{ message, claim }` → 这一轮由该来源开，调用方自带的输入若存在则入 `nextTurn` 排队；
3. 全部返回 `null` → 取 `nextTurn` 队首输入开轮；队列为空时才用调用方自带的输入。

来源可以消费 `nextTurn` 里自己先前放入的预留，也可以直接提供内容；运行时不做区分。

### 2.3 优先级

优先级是**三档固定层**，来源只能落在中间一层：

| 层 | 谁 | 说明 |
|---|---|---|
| 高 | 人类输入 | 已经排在 `nextTurn` 里、来源为 `user` 的输入永远先于任何来源开轮 |
| 中 | 轮次来源 | 按 `priority` 数值从高到低；未传时取 0；同值按登记顺序，先登记先用 |
| 低 | 调用方自带输入 | 以上都没有时才用 `chat()` 调用方带来的消息 |

来源**不能**越过人类输入；这是接口契约的一部分，不是单个来源自己的礼貌行为。

### 2.4 不抢占

来源之间不互相抢占：同一时刻只有一个来源得到开轮的询问机会并被采纳。多个来源都想开轮时，高优先级的那个赢；它返回 `null` 时下一个才有机会。

### 2.5 失败语义

按 DSH 的 goal 驱动器语义：

| 情况 | 结果 |
|---|---|
| 来源 `admit` 抛错 | 记警告、跳过该来源，继续问下一个（不打断这一轮） |
| 来源给了输入，但轮首持久化失败 | 本轮按失败结束，`reason=claim-failed`，`turn:end` 通知来源；来源决定是否记块（goal 记 `prompt-rejected` 并撤权） |
| 轮次在进入首个 step 前被拒绝（上游拒绝、拦截） | 本轮不计数；`turn:end` 带 `reason=prompt-rejected`，来源决定是否记块 |
| 来源自身逻辑抛错 | 记警告、撤掉该来源这一轮的预留；不得静默继续 |

**绝不静默继续**：任何让"来源要求的轮首持久化"没有发生的路径，都要么让本轮失败结束，要么把结果显式交给来源。

## 3 运行时与来源的分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| 实例 | 发事件；维护 `inbox`；维护 `turn.claim` / `turn.deferred`；提供领取、移除、回队 | 决定谁的轮先开 |
| 运行时 | 选实例；判忙；按 2.2/2.3 询问来源；开轮；把 `claim` 放进本轮 | 认识具体来源的业务 |
| 来源 | 判断"此刻要不要开轮"；提供输入与 claim；处理自己的失败 | 直接改实例的相位 |

## 4 与既有机制的关系

- **输入队列**：`inbox` 的队列语义、领取即消费、内存态与丢失取舍不变（`docs/agents/inbox.md`）。
- **轮次终止**：`[turn]` 日志与 `turn-end` 事件的 `status/reason` 契约不变（`docs/runtime/behavior.md`）。
- **bare 模式**：bare 轮次不发 `turn:start` / `turn:end`（无实例、无落库）；依赖这两个事件的来源不会在 bare 里工作。
- **工具延迟上下文**：工具在执行中提交的上下文进入 `turn.deferred`，由下一步之前的模型调用步骤追加到请求，不落库。

## 7 模块的挂载

功能模块不往运行时里接钩子，只在组合根挂载一次；模块自己完成登记与订阅：

- 模块导出一个 `mount(core)`（goal 是 `mountGoal(core, options)`），由 `core/index.js` 调用并把返回值挂到 `core` 上（如 `core.goals`）；
- 模块自己建自己的表、读写自己的数据（goal 的 `core/goal/store.js`），普通存储层只提供通用原语；
- 模块之间没有 import：一个模块只认 lifecycle 的两类接口、`runtime.chat` 与自己依赖的服务。

## 5 使用约束

- 新功能不允许在 `chat()`、loop 节点或工具执行器里加功能分支；需要开轮就用来源，需要感知轮次就用事件。
- 来源的状态必须能由持久事实重建（或明确接受进程内丢失），不得指望运行时替它保存。
- 事件订阅者不得在回调里同步阻塞长任务；需要等待的写成自己的队列。
